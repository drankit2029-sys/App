SECTION 1: ROOT CAUSES OF CURRENT FX FAILURES IN TAKEONE
================================================================================

Before adding new effects, five concrete bugs in the existing codebase prevent
the current effects panel from working reliably:

1. SILENT ABORT ON FIRST "APPLY" TAP (StudioFragment.java -> commitDspFx)
   - Current behavior: commitDspFx() executes:
       boolean hadSel = waveform.hasSelection();
       if (!hadSel && !ensureSelectionOrAutoEnable("Apply")) {
           return false;
       }
   - Why it fails: If the user opens the FX panel, enables effects, and taps
     "Apply" without first dragging selection handles on the waveform,
     ensureSelectionOrAutoEnable("Apply") turns on selection mode, shows a
     toast, and returns false without processing any audio.
   - Dead code consequence: Eight lines later in commitDspFx(), the branch
     `if (!hadSel) { dspBakedToRaw = true; ... }` is 100% unreachable because
     `!hadSel` always returned false above.

2. DOUBLE-PROCESSING ON PREVIEW AND SAVE (StudioFragment.java)
   - Current behavior: Because `dspBakedToRaw` is never set to `true` when
     applying FX to a selection (`hadSel == true`), `dspBakedToRaw` remains
     `false` while the FX slots remain enabled (`dspConfig.isActive() == true`).
   - Why it fails:
     (a) When the user presses Preview (`toggleStudioPreview()`), `livePreviewDsp`
         is created with `dspConfig` and processes the already-baked audio a
         second time during playback.
     (b) When the user presses Stop -> Save (`doSaveSequence()`), the check
         `if (dspConfig != null && dspConfig.isActive() && !dspBakedToRaw)`
         runs `EditEngine.applyDspToRange(raw, 0, totalFrames, chain, null)`
         across the entire file, double-baking the effects.

3. STREAMING ENCODER BYPASSES DSP (RecordingEngine.java / ConversionJobs.java)
   - Current behavior: While recording, `RecordingEngine.beginStreaming()`
     encodes raw microphone frames directly into a `.part` container file in
     parallel.
   - Why it fails: If `engine.abortStreaming()` is not called whenever the
     real-time FX chain is active, `ConversionJobs.dispatchSave()` adopts the
     pre-encoded `.part` file, completely ignoring any enabled FX in `dspConfig`
     that were not destructively baked into `raw`.

4. SINGLE-VALUE SLOT LIMITATION & HARDCODED PIPELINE ORDER (DspChain.java)
   - Current behavior: `DspChain.EffectSlot` only stores a single integer
     `public int value` (0..100%) and copies it into flat legacy fields
     (`noisePct`, `deEssPct`, `compPct`, etc.) via `syncLegacyFieldsFromSlots()`.
   - Why it fails:
     (a) Users cannot customize essential parameters (e.g., Compressor
         Threshold, Ratio, Attack, Release, Knee, Make-up Gain; or EQ Band
         Frequency, Gain dB, Q/Bandwidth, Filter Type).
     (b) Reordering slots in `dspConfig.slots` has zero effect on audio
         processing because `DspChain.processInPlace()` executes a fixed
         7-stage hardcoded sequence.
     (c) You cannot add multiple instances of an effect (e.g., two Notch
         filters or multiple Parametric EQ bands).
     (d) Stage 2 (Noise Suppression) and Stage 4 (Warmth/Presence) use crude
         1st-order single-pole RC smoothing (`y += alpha * (x - y)`) instead of
         proper biquad filters or STFT spectral processing.

5. MISSING BOUNDARY CROSSFADES & TAIL FLUSHING (EditEngine.java)
   - Current behavior: `EditEngine.applyDspToRange()` reads and overwrites
     4,096-frame blocks from `startFrame` to `endFrame` with zero crossfade at
     the selection boundaries.
   - Why it fails: Applying gain, EQ, phase, or dynamics changes to a sub-region
     creates a step discontinuity at `startFrame` and `endFrame` (audible click),
     and time-based effects (Reverb, Delay, Echo) have their tails abruptly
     chopped off at `endFrame`.

B1. Amplify (Audacity)
    - Mode: Offline Two-Pass (or Real-Time Trim when `Auto Peak` is off)
    - Parameters:

    - Algorithm: Pass 1 scans peak amplitude $P = \max |x[n]|$; Pass 2 applies
      scalar $g = 10^{	ext{dB}/20}$ (clamping $	ext{dB} \le -20\log_{10} P$

B2. Normalize (Audacity)
    - Mode: Offline Two-Pass
    - Parameters:
      * Remove DC Offset (`boolean`, default `true`)
      * Normalize Peak Amplitude (`boolean`, default `true`)
      * Target Peak Level (`-60.0 to 0.0 dBFS`, default `-1.0 dBFS`)
      * Normalize Stereo Channels Independently (`boolean`, default `false`)
    - Algorithm: Pass 1 computes per-channel mean $\mu_c = rac{1}{N}\sum x_c[n]$
      and DC-corrected peak $P_c = \max |x_c[n] - \mu_c|$; Pass 2 subtracts
      $\mu_c$ and multiplies by $10^{	ext{targetDb}/20} / P$.

B3. Loudness Normalization - EBU R128 / LUFS (Audacity)
    - Mode: Offline Two-Pass
    - Parameters:
      * Normalization Mode (`Perceived Loudness LUFS`, `RMS dBFS`)
      * Target Loudness (`-70.0 to 0.0 LUFS/dB`, default `-16.0 LUFS` for
        podcast/mobile, `-23.0 LUFS` for broadcast)
      * Treat Mono as Dual-Mono (`boolean`, default `true`)
      * True-Peak Limiter Ceiling (`-3.0 to -0.1 dBFS`, default `-1.0 dBFS`)
    - Algorithm: Pass 1 runs ITU-R BS.1770-4 K-weighting filter, computes
      400 ms block energies with 75% overlap, applies `-70 LUFS` absolute gate
      and `-10 LU` relative gate to find integrated LUFS; Pass 2 applies linear
      gain and a 2 ms lookahead true-peak limiter so peaks never clip.

    - Mode: Real-Time & Offline
    - Parameters:
      * Threshold (`-60.0 to -1.0 dBFS`, default `-18.0 dB`)

      * Ratio (`1.1:1 to 20.0:1`, default `3.0:1`)
      * Knee Width (`0.0 to 12.0 dB`, default `6.0 dB`)
      * Attack Time (`0.5 to 250.0 ms`, default `12.0 ms`)
